# 0003. 伊賀機の駆動系を映像から当てはめる

- 状態：採用
- 日付：2026-11-22

## 背景

駆動系の既定値（`src/mechanism/drive.ts`）は、トキハ本店（10B）の映像の起動（約 5 秒）と、説明書の停止（電磁ブレーキで 8〜10 秒）で決めていた。伊賀機に絞った（[0001](0001-model-iga-only.md)）ので、伊賀機の値に置き換える。

## 決定

伊賀機の映像から全音の回転数比 r(t)（公称に対する比）を追い、既存の駆動系モデルを最小二乗で当てはめた値を既定にする（`IGA_DRIVE_PARAMS`）。

| パラメータ | 値 | 意味 |
|---|---|---|
| slip | 0.0131 | 定常の滑り |
| startTorque | 0.64 | 起動トルク（最大トルク比） |
| kneeSlip | 0.054 | 最大トルクを出す滑り |
| inertia | 8.7 s | 慣性の時定数 |
| brakeTorque | 0.0165 | 電磁ブレーキ（劣化してごく弱い） |
| friction | 0 | 軸受の摩擦（当てはめで 0 になった） |
| openLoad | 0.02 | 据え置き（トキハの観察で 0.3% 以内） |

モデルの形（区分線形のトルク曲線＋空気負荷 ∝ 回転数²＋一定のブレーキ）は変えない。

## 根拠

### 測定の方法

`tools/track-speed.py`（このとき追加）を使った。全サイレンは歯車で剛結されているので、閉じたカバーからの漏れ音を含むすべての音が同じ比 r で動く。そこで各フレーム（8192 点・ホップ 1024）で、伊賀 8音の公称振動数とその第2倍音を r 倍した位置にあるスペクトルの和が最大になる r を探した。低速域は漏れ音が弱いので、予想値の近くに探索を絞って補った。

### 映像の中身（70 秒）

- 約 2.0 秒：START。漏れ音が扇形に上がる。
- 約 13.6 秒：定常（r = 0.98694）。
- 17.8〜39.4 秒：演奏（家路）。
- 40.3 秒：電源断。そこから映像の終わり（70 秒）まで惰性で下がり続ける。64.5 秒より後は編集の切れ目らしく、当てはめに使わない。

### 結果

- **滑り 1.31%**：定常 r = 0.98694。安定音 8 つ（354.9 / 399.2 / 443.4 / 473.0 / 532.1 / 591.2 / 665.0 / 709.7 Hz）も公称の 0.985〜0.987 倍。トキハの 3.8% よりずっと小さい。
- **起動**：START から定常の 2% 以内まで約 11.7 秒。8〜12 秒の加速はほぼ一定（約 0.09/s）で、最後に丸まって定常に入る。説明書の「起動後約 10〜15 秒」とよく合う。トキハ（約 5 秒）の解釈は機体の差だった。
- **停止**：電源断のあとの減速 dx/dt は x² にほぼ比例する（x = 0.95 で 0.031/s、0.81 で 0.021/s、0.64 で 0.014/s。x² で割るとどれも約 0.032）。つまり空気負荷だけでほぼ説明でき、ブレーキトルクは最大トルクの 1.7% しかない。説明書の「8〜10 秒」とは合わない。YMSHA の助言「停止時間は劣化具合による」（[0005](0005-ymsha-advice.md)）と合う。モデルで延長すると、完全に止まるまで約 3 分。
- 当てはめの残差：起動の中央値 0.0025、惰性の rms 0.0011（同期回転数比）。

| 時刻（電源断から） | 映像 | モデル |
|---|---|---|
| 10 秒 | 0.759 | 0.759 |
| 20 秒 | 0.609 | 0.608 |
| 24 秒 | 0.561 | 0.562 |

## 結果

- `src/mechanism/drive.ts`：`IGA_DRIVE_PARAMS` を追加し、`DEFAULT_DRIVE_PARAMS` にした。トキハの値は `TOKIWA_10B_DRIVE_PARAMS` に残した。
- `src/mechanism/drive.test.ts`：伊賀機の滑り、起動時間、一定加速、惰性の 3 点、止まるまでの時間（2〜4 分）をテストで固定した。トキハの起動・停止のテストも残した。
- `src/mechanism/autoplay.ts`：AUT の待ち時間を 15.8 秒にした（映像の START → 最初の音）。曲の終わりから電源断までは 0.9 秒。
- 残った課題：ブレーキの劣化具合は個体と時期で変わる。画面からパラメータを操作できるようにするのは UI の課題。50Hz 地域での動きは未検証（伊賀は 60Hz）。
